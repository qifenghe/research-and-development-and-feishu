## 2026-06-18 第三轮执行

已完成“研发人员接受任务 -> 实验单草稿 -> 提交内部测试”的内存版后端 API。

新增模型：

- ExperimentForm：实验单主记录，挂到具体任务和样品版本。
- ExperimentFormStatus：DRAFT、SUBMITTED_FOR_TEST、LOCKED。
- TestAssignment：内部测试任务。
- TestAssignmentStatus：PENDING_TEST、PASSED、FAILED_RESAMPLE。

新增接口：

- POST /api/v1/rnd-tasks/{id}/accept：研发人员接受任务，任务进入 SAMPLING。
- POST /api/v1/rnd-tasks/{id}/experiment-form/draft：保存实验单草稿，支持物料明细。
- POST /api/v1/experiment-forms/{id}/submit-test：提交实验单给内部测试人员，生成内部测试任务。

业务规则：

- 只有 PENDING_ACCEPTANCE 状态的任务可以接受。
- 只有被分发的研发人员可以接受任务。
- 只有 SAMPLING 状态的任务可以填写实验单草稿。
- 只有 DRAFT 状态的实验单可以提交内部测试。
- 提交内部测试后，研发任务状态进入 PENDING_TEST。

验证结果：

- mvn test：13 tests, 0 failures, 0 errors。
- node prototype-app/test-prototype.mjs：30 views, 29 navigation targets, 5 top-level modules。

下一步建议：

- 锁定后实验单不可覆盖修改，复打样时生成下一样品版本，如 A0 到 A1。

## 2026-06-18 第四轮执行

已完成“内部测试确认 -> 通过锁版 / 不通过复打样”的内存版后端 API。

新增模型：

- TestRecord：内部测试结果记录。
- PassInternalTestResult：内部测试通过返回对象。
- FailInternalTestResult：内部测试不通过复打样返回对象。

新增接口：

- POST /api/v1/test-assignments/{id}/pass：内部测试通过，锁定实验单，测试任务标记 PASSED，研发任务标记 COMPLETED。
- POST /api/v1/test-assignments/{id}/fail-resample：内部测试不通过，测试任务标记 FAILED_RESAMPLE，自动生成下一样品版本和复打样任务。

业务规则：

- 只有 PENDING_TEST 状态的内部测试任务可以确认。
- 只有被配置的测试人员可以确认测试结果。
- 测试通过后实验单状态变为 LOCKED，表示历史版本只读不可覆盖。
- 测试不通过复打样时，版本号按 A + 数字递增，例如 A0 自动生成 A1。
- 复打样任务会沿用原研发负责人，状态进入 PENDING_ACCEPTANCE，等待研发再次接受任务。

验证结果：

- mvn test：15 tests, 0 failures, 0 errors。
- node prototype-app/test-prototype.mjs：30 views, 29 navigation targets, 5 top-level modules。

## 2026-06-18 第五轮执行

已完成“寄样反馈 -> 生成核价文件 -> 通知财务核价”的内存版后端 API。

新增模型：

- ShipmentRecord：寄样记录，挂到具体样品版本。
- ShipmentStatus：SHIPPED、FEEDBACK_PASSED、FEEDBACK_FAILED_RESAMPLE、STOPPED。
- CustomerFeedback：客户/业务反馈记录。
- CustomerFeedbackResult：PASSED、FAILED_RESAMPLE、STOPPED。
- PricingFileRecord：核价文件元数据，记录文件名、核价版本、文件大小和状态。
- PricingFileStatus：GENERATED、FINANCE_NOTIFIED。
- FinanceNotification：财务核价通知记录。
- FinanceNotificationStatus：SENT。

新增接口：

- POST /api/v1/sample-versions/{id}/shipments：对指定样品版本创建寄样记录。
- POST /api/v1/shipments/{id}/feedback：提交寄样反馈，通过、复打样或停止。
- POST /api/v1/sample-versions/{id}/pricing-files：对指定样品版本生成核价 Excel 文件记录。
- POST /api/v1/pricing-files/{id}/notify-finance：通知财务核价，记录通知状态。

业务规则：

- 寄样记录必须关联具体样品版本。
- 寄样前样品版本必须已有 LOCKED 状态的实验单，避免未通过内部测试的样品流出。
- 寄样反馈只能对 SHIPPED 状态的寄样记录提交一次。
- 生成核价文件前，样品版本必须已有 LOCKED 状态的实验单。
- 核价文件使用锁定实验单里的物料明细生成，避免草稿数据被误用。
- 同一样品版本多次生成核价文件时，核价版本自动递增：A0-核价V1、A0-核价V2。
- 通知财务后，核价文件状态变更为 FINANCE_NOTIFIED。

本轮还修复了测试环境问题：

- 新增 src/test/resources/mockito-extensions/org.mockito.plugins.MockMaker。
- 指定 Mockito 使用 mock-maker-subclass，避免本机 JDK 环境下 inline mock maker self-attach 失败影响测试运行。
