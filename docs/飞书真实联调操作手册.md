# 飞书真实联调操作手册

本文档用于把“研发样品管理系统”从本地模拟飞书切换到真实飞书自建应用联调。目标是先跑通一个可展示效果：研发总监分发任务后，指定研发人员在飞书里收到消息卡片，并能点击进入系统或通过卡片按钮接受任务。

## 一、当前系统已具备的飞书能力

后端已经具备以下接口：

| 能力 | 接口 | 用途 |
| --- | --- | --- |
| 飞书用户绑定 | `POST /api/v1/feishu/users/bind` | 把飞书 `user_id` 绑定为系统用户和角色 |
| 飞书免登回调 | `POST /api/v1/feishu/oauth/callback` | 前端拿到飞书 `code` 后换取系统登录身份 |
| 集成状态检查 | `GET /api/v1/feishu/integration/status` | 查看当前是 MOCK 还是 OPENAPI，以及配置是否完整 |
| 待发送通知 | `GET /api/v1/feishu/notifications/pending` | 查看任务分发后生成的飞书通知队列 |
| 通知派发 | `POST /api/v1/feishu/notifications/dispatch` | 将待发送通知发到飞书 |
| 卡片按钮回调 | `POST /api/v1/feishu/card-actions` | 支持研发人员从卡片按钮接受研发任务 |
| 核价文件直连下载 | `GET /api/v1/pricing-files/{id}/download` | 财务或研发内勤按核价文件 ID 下载 Excel |

当前联调重点：

1. 真实获取 `tenant_access_token`。
2. 真实发送飞书消息卡片。
3. 消息卡片能跳转到系统页面。
4. 卡片按钮能回调后端并接受任务。

## 二、你需要在飞书后台准备的内容

进入飞书开放平台，创建或打开企业自建应用，准备以下信息：

| 项目 | 示例 | 说明 |
| --- | --- | --- |
| App ID | `cli_xxx` | 后端环境变量 `FEISHU_APP_ID` |
| App Secret | `xxxxx` | 后端环境变量 `FEISHU_APP_SECRET`，不要发到聊天里 |
| 应用可见范围 | 研发内勤、研发总监、研发、测试、财务 | 先小范围联调 |
| 前端 HTTPS 地址 | `https://xxx.example.com/` | 飞书工作台入口和卡片跳转地址 |
| 后端 HTTPS 地址 | `https://xxx.example.com/api/v1` | 飞书回调和 OpenAPI 访问地址 |
| 卡片回调密钥 | 随机字符串 | 对应 `FEISHU_CARD_ACTION_SECRET` |

建议先准备 5 个测试账号：

| 角色 | 用途 |
| --- | --- |
| 研发内勤 | 录入样品需求 |
| 研发总监 | 审核需求、分发任务 |
| 研发人员 | 接收飞书任务、填写实验单 |
| 内部测试人员 | 接收测试通知、确认测试结果 |
| 财务人员 | 接收核价通知 |

## 三、飞书应用后台配置建议

### 1. 应用首页地址

配置为前端访问地址：

```text
https://your-domain.example.com/
```

临时联调时可以使用 `ngrok` 或 `cloudflared` 生成的 HTTPS 地址。

### 2. 重定向 URL / 免登地址

如果飞书后台要求配置重定向地址，先配置为：

```text
https://your-domain.example.com/
```

前端后续拿到飞书 `code` 后调用：

```text
POST https://your-domain.example.com/api/v1/feishu/oauth/callback
```

### 3. 消息卡片跳转地址

后端发送消息卡片时会使用：

```text
FEISHU_APP_URL + "#rnd-module"
FEISHU_APP_URL + "#task-pool"
FEISHU_APP_URL + "#pricing-list"
```

因此 `FEISHU_APP_URL` 必须是飞书移动端和 PC 端都能打开的 HTTPS 地址。

### 4. 卡片按钮回调地址

配置或网关转发到：

```text
POST https://your-domain.example.com/api/v1/feishu/card-actions
```

请求头需带：

```text
X-Feishu-Card-Secret: 你配置的 FEISHU_CARD_ACTION_SECRET
```

当前后端支持的卡片动作：

```json
{
  "action": "ACCEPT_RND_TASK",
  "businessType": "RND_TASK",
  "businessId": "TASK-0001",
  "feishuUserId": "ou_xxx"
}
```

## 四、本机或服务器启动方式

本项目已经准备好本地飞书配置文件：

```text
backend/.env.feishu.local
```

该文件已被 `.gitignore` 忽略，不会提交到 GitHub。你只需要打开它填写真实值：

```bash
FEISHU_MODE=OPENAPI
FEISHU_BASE_URL=https://open.feishu.cn
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=你的真实 App Secret
FEISHU_APP_URL=https://your-domain.example.com/
FEISHU_CARD_ACTION_SECRET=你自定义的随机密钥
```

如果本地文件丢失，可以从模板重新复制：

```bash
cp backend/.env.feishu.example backend/.env.feishu.local
```

填写真实配置后，推荐用本地启动脚本启动后端。脚本会自动读取 `backend/.env.feishu.local`，不用手工 `source`：

```bash
node scripts/run-backend-local.mjs
```

如果后端端口要改成 `8081`：

```bash
node scripts/run-backend-local.mjs --port 8081
```

启动前后都可以运行本地自检脚本：

```bash
node scripts/feishu-local-check.mjs
```

自检脚本会检查：

- `backend/.env.feishu.local` 是否存在。
- `FEISHU_MODE` 是否为 `OPENAPI`。
- `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_APP_URL`、`FEISHU_CARD_ACTION_SECRET` 是否仍是占位符。
- 后端 `/api/v1/feishu/integration/status` 是否可访问。
- 后端返回的 `readyForOpenApi` 是否为 `true`。

如果后端不是默认端口，可以指定地址：

```bash
node scripts/feishu-local-check.mjs --backend-url http://127.0.0.1:8081
```

再启动前端原型：

```bash
cd prototype-app
python3 -m http.server 4174
```

如果使用内网穿透，需要把本地端口映射为 HTTPS：

| 服务 | 本地端口 | 用途 |
| --- | --- | --- |
| 前端原型 | 4174 | 飞书应用入口、消息卡片跳转 |
| 后端 API | 8080 | 飞书回调、通知派发、业务接口 |

## 五、联调演示路径

### 第 1 步：检查集成状态

```bash
curl https://your-domain.example.com/api/v1/feishu/integration/status
```

期望：

```json
{
  "code": "SUCCESS",
  "data": {
    "mode": "OPENAPI",
    "appIdConfigured": true,
    "appSecretConfigured": true
  }
}
```

### 第 2 步：绑定飞书用户

对每个测试人员执行一次：

```bash
curl -X POST https://your-domain.example.com/api/v1/feishu/users/bind \
  -H "Content-Type: application/json" \
  -d '{
    "name": "张研发",
    "feishuUserId": "ou_xxx",
    "role": "RND",
    "departmentName": "研发部"
  }'
```

推荐角色编码：

| 角色 | role |
| --- | --- |
| 研发内勤 | `RND_ASSISTANT` |
| 研发总监 | `RND_DIRECTOR` |
| 研发人员 | `RND` |
| 内部测试人员 | `TESTER` |
| 财务人员 | `FINANCE` |
| 管理层 | `MANAGER` |
| 管理员 | `ADMIN` |

### 第 3 步：制造一条研发任务并分发

业务路径：

1. 研发内勤创建样品需求。
2. 研发总监审核通过。
3. 研发总监把任务分发给已绑定飞书用户的研发人员。

分发成功后，系统会生成一条 `PENDING_SEND` 飞书通知。

推荐用本地演示脚本自动完成以上步骤：

```bash
node scripts/feishu-demo-task.mjs \
  --backend-url http://127.0.0.1:8080 \
  --engineer-name 张研发 \
  --engineer-feishu-user-id ou_xxx
```

脚本会自动完成：

- 绑定演示研发内勤、研发总监、研发人员。
- 通过 mock 免登获取系统 token。
- 创建样品需求。
- 研发总监审核。
- 研发总监分发给指定研发人员。
- 查询待发送通知。

默认情况下脚本只生成 `PENDING_SEND` 通知，不会真实发送飞书消息。确认要派发时再增加：

```bash
node scripts/feishu-demo-task.mjs \
  --backend-url http://127.0.0.1:8080 \
  --engineer-name 张研发 \
  --engineer-feishu-user-id ou_xxx \
  --dispatch
```

真实 `OPENAPI` 模式下，`--dispatch` 会调用飞书发送接口，请确认研发人员 `user_id` 填写正确后再使用。

安全限制：

- 如果使用 `--dispatch`，脚本会拒绝默认演示 ID `ou_demo_engineer`。
- 必须通过 `--engineer-feishu-user-id ou_xxx` 填写真实研发人员飞书 user_id。
- 这样可以避免误向不存在的演示用户派发真实飞书消息。

### 第 4 步：查看待发送通知

```bash
curl https://your-domain.example.com/api/v1/feishu/notifications/pending
```

期望能看到：

```json
{
  "businessType": "RND_TASK",
  "recipientFeishuUserId": "ou_xxx",
  "templateKey": "TASK_ASSIGNED"
}
```

### 第 5 步：派发飞书通知

```bash
curl -X POST https://your-domain.example.com/api/v1/feishu/notifications/dispatch
```

期望：

```json
{
  "sentCount": 1,
  "failedCount": 0
}
```

此时研发人员应在飞书里收到任务消息卡片。

### 第 6 步：点击卡片或按钮

演示效果：

- 点击“查看任务”：打开系统任务页面。
- 点击“接受任务”：后端收到卡片动作，任务状态从 `PENDING_ACCEPTANCE` 变为 `SAMPLING`。

### 第 7 步：核价文件下载验证

样品测试通过、客户反馈通过并生成核价文件后，可以直接用核价文件 ID 下载 Excel：

```bash
curl -L -OJ https://your-domain.example.com/api/v1/pricing-files/PRICE-0001/download
```

期望：

- 浏览器或命令行下载到 `.xlsx` 文件。
- 文件名保持类似 `500g香卤大肠头-核价原料清单-A0-V1.xlsx`。
- 研发内勤、研发总监、财务、管理层可下载；测试人员默认不可下载。

## 六、常见问题排查

| 问题 | 优先检查 |
| --- | --- |
| 找不到 `.env.feishu.local` | 这是 macOS 隐藏文件，可在 Finder 按 `Command + Shift + .` 显示；它是纯文本文件，可用 VS Code、Cursor、文本编辑打开 |
| 集成状态仍是 MOCK | `FEISHU_MODE` 是否等于 `OPENAPI` |
| 获取 token 失败 | `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 是否正确 |
| 消息发不出去 | 应用是否有发送消息权限、用户是否在应用可见范围 |
| 飞书打不开卡片链接 | `FEISHU_APP_URL` 是否是手机可访问 HTTPS |
| 卡片按钮 401/鉴权失败 | `X-Feishu-Card-Secret` 是否和后端一致 |
| 找不到用户 | 是否先调用 `/feishu/users/bind` 绑定了对应 `feishuUserId` |
| 研发人员收不到通知 | 分发任务时填写的研发人员姓名是否和绑定用户姓名一致 |

## 七、给飞书管理员的最小配置清单

请飞书管理员协助确认：

1. 自建应用已创建。
2. 已拿到 `App ID` 和 `App Secret`。
3. 应用可见范围包含联调测试人员。
4. 已开通发送消息权限。
5. 已开通获取用户身份/免登相关权限。
6. 应用首页配置为 HTTPS 前端地址。
7. 卡片回调或网关转发能到 HTTPS 后端地址。
8. 联调人员能在飞书工作台看到该应用。

## 八、首轮验收标准

首轮真实联调完成的标准：

1. `/api/v1/feishu/integration/status` 显示 `OPENAPI` 且配置完整。
2. 研发人员飞书账号绑定成功。
3. 任务分发后生成待发送通知。
4. 通知派发后研发人员真实收到飞书消息卡片。
5. 消息卡片能打开系统页面。
6. 卡片按钮能接受研发任务。

达到以上 6 条，就可以给你做第一版真实效果演示。
