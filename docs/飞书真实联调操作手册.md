# 飞书真实联调操作手册

本文档用于把“研发样品管理系统”从本地模拟飞书切换到真实飞书自建应用联调。目标是先跑通一个可展示效果：研发总监分发任务后，指定研发人员在飞书里收到消息卡片，并能点击进入系统或通过卡片按钮接受任务。

## 一、当前系统已具备的飞书能力

后端已经具备以下接口：

| 能力 | 接口 | 用途 |
| --- | --- | --- |
| 飞书用户绑定 | `POST /api/v1/feishu/users/bind` | 把飞书 `user_id` 绑定为系统用户和角色 |
| 飞书免登回调 | `POST /api/v1/feishu/oauth/callback` | 前端拿到飞书 `code` 后换取系统登录身份 |
| 集成状态检查 | `GET /api/v1/feishu/integration/status` | 查看当前是 MOCK 还是 OPENAPI，以及配置是否完整 |
| 待发送通知 | `GET /api/v1/feishu/notifications/pending` | 查看任务分发后生成的飞书通知队列 |
| 通知派发 | `POST /api/v1/feishu/notifications/dispatch` | 将待发送通知发到飞书 |
| 卡片按钮回调 | `POST /api/v1/feishu/card-actions` | 支持研发人员从卡片按钮接受研发任务 |
| 核价文件直连下载 | `GET /api/v1/pricing-files/{id}/download` | 财务或研发内勤按核价文件 ID 下载 Excel |

当前联调重点：

1. 真实获取 `tenant_access_token`。
2. 真实发送飞书消息卡片。
3. 消息卡片能跳转到系统页面。
4. 卡片按钮能回调后端并接受任务。

## 二、你需要在飞书后台准备的内容

进入飞书开放平台，创建或打开企业自建应用，准备以下信息：

| 项目 | 示例 | 说明 |
| --- | --- | --- |
| App ID | `cli_xxx` | 后端环境变量 `FEISHU_APP_ID` |
| App Secret | `xxxxx` | 后端环境变量 `FEISHU_APP_SECRET`，不要发到聊天里 |
| 应用可见范围 | 研发内勤、研发总监、研发、测试、财务 | 先小范围联调 |
| 前端 HTTPS 地址 | `https://xxx.example.com/` | 飞书工作台入口和卡片跳转地址 |
| 后端 HTTPS 地址 | `https://xxx.example.com/api/v1` | 飞书回调和 OpenAPI 访问地址 |
| 卡片回调密钥 | 随机字符串 | 对应 `FEISHU_CARD_ACTION_SECRET` |

建议先准备 5 个测试账号：

| 角色 | 用途 |
| --- | --- |
| 研发内勤 | 录入样品需求 |
| 研发总监 | 审核需求、分发任务 |
| 研发人员 | 接收飞书任务、填写实验单 |
| 内部测试人员 | 接收测试通知、确认测试结果 |
| 财务人员 | 接收核价通知 |

## 三、飞书应用后台配置建议

### 1. 应用首页地址

Vue 双前端请分别配置：

```text
桌面端主页：https://your-domain.example.com/admin/dashboard
移动端主页：https://your-domain.example.com/m/todo
```

临时联调可使用 `cloudflared` 生成的 HTTPS 根地址，再拼上述路径。

一键启动本地联调栈（含网关 + 可选 HTTPS 隧道）：

```bash
node scripts/run-feishu-dev.mjs
```

打印飞书后台配置清单：

```bash
node scripts/print-feishu-config.mjs https://your-tunnel.trycloudflare.com
```

### 2. 重定向 URL / 免登地址

飞书后台建议添加两条重定向 URL：

```text
https://your-domain.example.com/admin/login/callback
https://your-domain.example.com/m/login/callback
```

前端拿到飞书 `code` 后调用：

```text
POST https://your-domain.example.com/api/v1/feishu/oauth/callback
```

### 3. 消息卡片跳转地址

后端发送消息卡片时会使用：

```text
FEISHU_APP_URL + "/m/tasks/{taskId}"
FEISHU_APP_URL + "/admin/dashboard"
```

因此 `FEISHU_APP_URL` 必须填写**统一网关根地址**（不带 `/admin` 或 `/m` 后缀），且必须是飞书移动端和 PC 端都能打开的 HTTPS 地址。

### 4. 卡片按钮回调地址

配置或网关转发到：

```text
POST https://your-domain.example.com/api/v1/feishu/card-actions
```

请求头需带：

```text
X-Feishu-Card-Secret: 你配置的 FEISHU_CARD_ACTION_SECRET
```

当前后端支持的卡片动作：

```json
{
  "action": "ACCEPT_RND_TASK",
  "businessType": "RND_TASK",
  "businessId": "TASK-0001",
  "feishuUserId": "ou_xxx"
}
```

## 四、本机或服务器启动方式

本项目已经准备好本地飞书配置文件：

```text
backend/.env.feishu.local
```

该文件已被 `.gitignore` 忽略，不会提交到 GitHub。你只需要打开它填写真实值：

```bash
FEISHU_MODE=OPENAPI
FEISHU_BASE_URL=https://open.feishu.cn
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=你的真实 App Secret
FEISHU_APP_URL=https://your-domain.example.com/
FEISHU_CARD_ACTION_SECRET=你自定义的随机密钥
```

如果本地文件丢失，可以从模板重新复制：

```bash
cp backend/.env.feishu.example backend/.env.feishu.local
```

填写真实配置后，推荐用本地启动脚本启动后端。脚本会自动读取 `backend/.env.feishu.local`，不用手工 `source`。脚本默认使用 `local` profile，本地会用 H2 内存库启动，适合联调演示；如果要连接 `application.yml` 里的 PostgreSQL 配置，可以追加 `--profile default`：

```bash
node scripts/run-backend-local.mjs
```

如果后端端口要改成 `8081`：

```bash
node scripts/run-backend-local.mjs --port 8081
```

启动前后都可以运行本地自检脚本：

```bash
node scripts/feishu-local-check.mjs
```

自检脚本会检查：

- `backend/.env.feishu.local` 是否存在。
- `FEISHU_MODE` 是否为 `OPENAPI`。
- `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_APP_URL`、`FEISHU_CARD_ACTION_SECRET` 是否仍是占位符。
- 后端 `/api/v1/feishu/integration/status` 是否可访问。
- 后端返回的 `readyForOpenApi` 是否为 `true`。
- `FEISHU_APP_URL` 是否是合法 URL；如果不是 HTTPS，会给出警告。
- 最后一行会输出“下一步”，例如：
  - 需要补齐 `backend/.env.feishu.local`。
  - 需要运行 `node scripts/run-backend-local.mjs` 启动后端。
- 后端需要用本地 env 重新启动。
  - 可以进入真实飞书通知派发联调。

如果后端不是默认端口，可以指定地址：

```bash
node scripts/feishu-local-check.mjs --backend-url http://127.0.0.1:8081
```

说明：`FEISHU_APP_URL` 警告不会阻塞后端 OpenAPI 联调，但会影响飞书消息卡片里的“查看详情”按钮。真实手机端演示时，建议填写手机可访问的 HTTPS 地址，例如公司 HTTPS 域名、内网安全网关地址，或临时 HTTPS 隧道地址。

如果要直接做一轮演示，需要区分两种模式：

1. `OPENAPI` 真实飞书模式：用于验证真实 App ID、App Secret、tenant access token 和消息派发。此模式下不能使用 `mock:` 免登码创建完整演示链路，必须走真实飞书免登或提供后端已登录 token。
2. `MOCK` 演示数据模式：用于在本地快速生成样品需求、任务、实验单、寄样、核价文件和待发送通知，不会调用真实飞书接口。

联调向导适合在 `MOCK` 演示数据模式下快速造数。它会自动创建完整演示链路：

- 研发内勤创建样品需求。
- 研发总监审核通过并分发研发任务。
- 研发人员接受任务。
- 研发人员保存实验单草稿。
- 提交内部测试并测试通过，锁定实验版本。
- 创建寄样记录并录入客户通过反馈。
- 生成核价 Excel 文件。
- 生成财务核价通知。
- 生成飞书待发送通知，默认不真实派发。

第一次使用前，先复制演示人员模板并填写真实联调人员：

```bash
cp .feishu-demo.local.example .feishu-demo.local
```

`.feishu-demo.local` 已经加入 `.gitignore`，不会提交到 GitHub。填好后可以直接运行：

```bash
node scripts/feishu-demo-wizard.mjs
```

运行成功后，终端会输出本轮演示生成的关键编号，并附带“演示核对清单”。如果 `backend/.env.feishu.local` 中已经配置 `FEISHU_APP_URL`，清单会直接输出 Vue 双前端完整页面链接；如果未配置，则显示页面标识。可以按清单打开 PC 管理端页面逐项核对：

| 核对项 | 页面标识 | 核对内容 |
| --- | --- | --- |
| 工作台查看样品编号 | `#dashboard` | `sampleNo` |
| 研发任务查看任务编号 | `#rnd-module` | `taskId` |
| 实验单历史查看实验单 | `#experiment-history` | `experimentFormId` |
| 寄样核价查看寄样记录 | `#shipment-pricing-module` | `shipmentId` |
| 核价文件查看文件记录 | `#pricing-list` | `pricingFileId` |
| 财务通知查看通知记录 | `#pricing-detail` | `financeNotificationId` |

如果需要给演示留档，或者后续接自动化核验，可以追加 `--json` 输出机器可读结果：

```bash
node scripts/feishu-demo-wizard.mjs --json
```

JSON 中会包含 `sampleNo`、关键业务 ID、`pendingCount`、`dispatchResult` 和完整核对清单。

演示前可以把 JSON 保存下来并校验完整性，校验会检查关键 ID、核对项数量、清单是否覆盖样品编号和关键业务编号、页面标识、URL 格式、URL 路径与 route 是否一致，以及 Vue 双前端页面是否存在：

```bash
node scripts/feishu-demo-wizard.mjs --json > /tmp/feishu-demo-report.json
node scripts/feishu-demo-report.mjs --file /tmp/feishu-demo-report.json \
  --pc-router frontend/apps/pc/src/router/index.ts \
  --mobile-router frontend/apps/mobile/src/router/index.ts
```

校验结果会输出“下一步”。如果未通过，按提示修正 JSON、确认 `--pc-router` / `--mobile-router` 指向最新前端路由文件，或重新运行联调向导生成报告。

也可以在命令行临时覆盖某些人员或后端地址：

```bash
node scripts/feishu-demo-wizard.mjs \
  --demo-config-file .feishu-demo.local \
  --backend-url http://127.0.0.1:8080 \
  --assistant-name 李内勤 \
  --assistant-feishu-user-id ou_assistant_xxx \

```

默认只生成待发送通知，不会真实发送。确认要发到飞书时再追加 `--dispatch`：

```bash
node scripts/feishu-demo-wizard.mjs \
  --demo-config-file .feishu-demo.local \
  --backend-url http://127.0.0.1:8080 \
  --assistant-name 李内勤 \
  --assistant-feishu-user-id ou_assistant_xxx \
  --director-name 王总监 \
  --director-feishu-user-id ou_director_xxx \
  --engineer-name 张研发 \
  --engineer-feishu-user-id ou_xxx \
  --tester-name 内部测试员 \
  --finance-recipient-name 财务核价员 \
  --dispatch
```

再启动前端。真实飞书体验推荐直接使用一键联调栈，它会同时启动后端、PC 前端、移动端、统一网关，并在检测到 `cloudflared` 时自动生成 HTTPS 隧道：

```bash
node scripts/run-feishu-dev.mjs
```

也可以手动分别启动 Vue 双前端：

```bash
cd frontend
pnpm install
pnpm dev:pc      # http://localhost:5173/admin/
pnpm dev:mobile  # http://localhost:5174/m/
```

旧版静态原型只作为历史设计对照，不参与真实飞书联调主流程。

飞书应用主页建议配置为：

| 端 | 主页 URL |

| 后端 API | 8080 | 飞书回调、通知派发、业务接口 |

## 五、联调演示路径

### 第 1 步：检查集成状态

```bash
curl https://your-domain.example.com/api/v1/feishu/integration/status
```

期望：

```json
{
  "code": "SUCCESS",
  "data": {
    "mode": "OPENAPI",
    "appIdConfigured": true,
    "appSecretConfigured": true
  }
}
```

### 第 2 步：绑定飞书用户

对每个测试人员执行一次：

```bash
curl -X POST https://your-domain.example.com/api/v1/feishu/users/bind \
  -H "Content-Type: application/json" \
  -d '{
    "name": "张研发",
    "feishuUserId": "ou_xxx",
    "role": "RND",
    "departmentName": "研发部"
  }'
```

推荐角色编码：

| 角色 | role |
| --- | --- |
| 研发内勤 | `RND_ASSISTANT` |
| 研发总监 | `RND_DIRECTOR` |
| 研发人员 | `RND` |
| 内部测试人员 | `TESTER` |
| 财务人员 | `FINANCE` |
| 管理层 | `MANAGER` |
| 管理员 | `ADMIN` |

### 第 3 步：制造一条完整演示链路

业务路径：

1. 研发内勤创建样品需求。
2. 研发总监审核通过。
3. 研发总监把任务分发给已绑定飞书用户的研发人员。
4. 研发人员接受任务并填写实验单草稿。
5. 提交内部测试，测试通过后锁定实验版本。
6. 登记寄样和客户通过反馈。
7. 生成核价 Excel 文件。
8. 通知财务核价。

分发成功后，系统会生成一条 `PENDING_SEND` 飞书任务通知；核价文件和财务通知也会写入系统记录。

推荐用本地演示脚本自动完成以上步骤：

```bash
node scripts/feishu-demo-task.mjs \
  --backend-url http://127.0.0.1:8080 \
  --engineer-name 张研发 \
  --engineer-feishu-user-id ou_xxx \
  --tester-name 内部测试员 \
  --finance-recipient-name 财务核价员
```

脚本会自动完成：

- 绑定演示研发内勤、研发总监、研发人员。
  - 通过 mock 免登获取系统 token。
- 创建样品需求。
- 研发总监审核。
- 研发总监分发给指定研发人员。
- 研发人员接受任务。
- 保存实验单草稿。
- 提交内部测试并通过。
- 创建寄样记录和客户通过反馈。
- 生成核价 Excel 文件。
- 生成财务核价通知。
- 查询待发送通知。

默认情况下脚本只生成 `PENDING_SEND` 通知，不会真实发送飞书消息。确认要派发时再增加：

```bash
node scripts/feishu-demo-task.mjs \
  --backend-url http://127.0.0.1:8080 \
  --engineer-name 张研发 \
  --engineer-feishu-user-id ou_xxx \
  --tester-name 内部测试员 \
  --finance-recipient-name 财务核价员 \
  --dispatch
```

真实 `OPENAPI` 模式下，不能用 `mock:` 免登码生成完整演示数据；如果直接运行上述演示脚本，飞书会返回 `code is invalid`。这是预期保护。要做真实派发联调，请先通过真实飞书免登完成登录，或由前端/后端提供真实登录 token 后再调用业务接口。

安全限制：

- 如果使用 `--dispatch`，脚本会拒绝默认演示 ID `ou_demo_engineer`。
- 必须通过 `--engineer-feishu-user-id ou_xxx` 填写真实研发人员飞书 user_id。
- 这样可以避免误向不存在的演示用户派发真实飞书消息。

### 第 4 步：查看待发送通知

```bash
curl https://your-domain.example.com/api/v1/feishu/notifications/pending
```

期望能看到：

```json
{
  "businessType": "RND_TASK",
  "recipientFeishuUserId": "ou_xxx",
  "templateKey": "TASK_ASSIGNED"
}
```

### 第 5 步：派发飞书通知

```bash
curl -X POST https://your-domain.example.com/api/v1/feishu/notifications/dispatch
```

期望：

```json
{
  "sentCount": 1,
  "failedCount": 0
}
```

此时研发人员应在飞书里收到任务消息卡片。

### 第 6 步：点击卡片或按钮

演示效果：

- 点击“查看任务”：打开系统任务页面。
- 点击“接受任务”：后端收到卡片动作，任务状态从 `PENDING_ACCEPTANCE` 变为 `SAMPLING`。

### 第 7 步：核价文件下载验证

样品测试通过、客户反馈通过并生成核价文件后，可以直接用核价文件 ID 下载 Excel：

```bash
curl -L -OJ https://your-domain.example.com/api/v1/pricing-files/PRICE-0001/download
```

期望：

- 浏览器或命令行下载到 `.xlsx` 文件。
- 文件名保持类似 `500g香卤大肠头-核价原料清单-A0-V1.xlsx`。
- 研发内勤、研发总监、财务、管理层可下载；测试人员默认不可下载。

## 六、常见问题排查

| 问题 | 优先检查 |
| --- | --- |
| 找不到 `.env.feishu.local` | 这是 macOS 隐藏文件，可在 Finder 按 `Command + Shift + .` 显示；它是纯文本文件，可用 VS Code、Cursor、文本编辑打开 |
| 集成状态仍是 MOCK | `FEISHU_MODE` 是否等于 `OPENAPI` |
| 获取 token 失败 | `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 是否正确 |
| 演示脚本报 `code is invalid` | 当前是 `OPENAPI` 真实模式，不能使用 `mock:` 免登码；切回 `MOCK` 造演示数据，或改走真实飞书免登链路 |
| 消息发不出去 | 应用是否有发送消息权限、用户是否在应用可见范围 |
| 飞书打不开卡片链接 | `FEISHU_APP_URL` 是否是手机可访问 HTTPS |
| 卡片按钮 401/鉴权失败 | `X-Feishu-Card-Secret` 是否和后端一致 |
| 找不到用户 | 是否先调用 `/feishu/users/bind` 绑定了对应 `feishuUserId` |
| 研发人员收不到通知 | 分发任务时填写的研发人员姓名是否和绑定用户姓名一致 |

## 七、给飞书管理员的最小配置清单

请飞书管理员协助确认：

1. 自建应用已创建。
2. 已拿到 `App ID` 和 `App Secret`。
3. 应用可见范围包含联调测试人员。
4. 已开通发送消息权限。
