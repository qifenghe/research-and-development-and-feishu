# 飞书自建应用研发样品管理系统完整开发任务清单

版本：V1.0  
日期：2026-06-18  
范围：研发样品管理闭环  
系统终点：样品通过后生成核价 Excel 文件，并通过飞书通知财务核价  

## 1. 当前范围确认

### 1.1 本期建设目标

建设一套“飞书自建应用 + 自研后端 + PC 管理端 + 手机/平板录入端”的研发样品管理系统，用来替代纸质打样记录，实现研发样品从需求录入到核价文件生成的闭环管理。

核心解决问题：

1. 研发实验现场直接录入，减少纸质记录字迹不清、二次录入歧义。
2. 实验单、测试记录、寄样反馈、核价文件按样品版本归档。
3. 样品版本支持 `A0、A1、A2、A3...` 持续递增，不限制版本数量。
4. 实验单保存草稿后可继续编辑，内部测试通过后提交并锁定版本。
5. 锁定后的历史版本只读，可查阅、可导出、可归档。
6. 样品通过后生成核价 Excel 文件，核价文件也需要版本管理。
7. 通过飞书自建应用完成免登、任务通知、待办跳转、财务通知。

### 1.2 本期不包含

1. 不做采购询价模块。
2. 不做完整财务成本核算模块。
3. 不做工艺文件生成模块。
4. 不做产品 BOM 正式录入模块。
5. 不做 ERP、MES、WMS 深度集成，后续可预留接口。

### 1.3 推荐技术栈

| 层级 | 技术 |
|---|---|
| 飞书入口 | 飞书自建应用、免登 OAuth、消息卡片、事件订阅 |
| PC 前端 | Vue 3 + Ant Design Vue |
| 手机/平板前端 | Vue 3 + Vant |
| 后端 | Java 17 + Spring Boot 3 |
| 数据库 | PostgreSQL |
| 缓存/异步 | Redis |
| 文件存储 | MinIO 优先，NAS 可作为底层挂载或备份 |
| Excel 生成 | EasyExcel + Apache POI |
| 部署 | Docker Compose + Nginx + HTTPS |
| 日志审计 | Spring AOP + AuditLog 表 |

```text
-> 核价文件归档
-> 飞书通知财务核价
```

## 7. 关键业务规则

### 7.1 样品版本规则

1. 每个样品项目至少有一个版本，从 A0 开始。
2. 每次复打样生成下一版本。
3. 版本号不限制数量，规则为 `A + version_no`。
4. 示例：

| version_no | 展示版本 |
|---|---|
| 0 | A0 |
| 1 | A1 |
| 2 | A2 |
| 3 | A3 |
| 10 | A10 |

### 7.2 实验单锁定规则

1. 实验单保存草稿时可以修改。
2. 实验单提交测试后，研发人员原则上不能随意改关键数据。
3. 测试通过后，当前实验单锁定。
4. 锁定后的实验单只能查看、导出、归档，不能覆盖修改。
5. 如果后续需要调整，必须生成下一样品版本。

### 7.3 核价文件版本规则

1. 核价文件必须关联具体样品版本。
2. 同一样品版本可以生成多份核价文件。
3. 不允许覆盖旧核价文件。
4. 命名示例：

```text
A0-核价V1
A0-核价V2
A3-核价V1
A3-核价V2
```

### 7.4 文件归档规则

建议归档路径：

```text
样品档案/
  客户名称/
    样品编号_产品名称/
      A0/
        需求单/
        实验单/
        测试记录/
        寄样反馈/
        核价文件/
        附件照片/
      A1/
      A2/
      A3/
```

| UAT-005 | 研发手机端填写实验单并保存 | 草稿可再次编辑 |
| UAT-006 | 研发提交内部测试 | 测试人员收到通知 |
| UAT-007 | 测试通过 | 实验单锁定，历史版本可查 |
| UAT-008 | 测试不通过 | 自动生成下一版本 A1 |
| UAT-009 | A3 复打样 | 自动生成 A4 |
| UAT-010 | 寄样反馈通过 | 可生成核价文件 |
| UAT-011 | 直接生成核价文件 | 不寄样也可生成核价 Excel |
| UAT-012 | 同一版本再次生成核价 | 生成 V2，不覆盖 V1 |
| UAT-013 | 通知财务 | 财务收到飞书消息和文件链接 |
| UAT-014 | 搜索样品 | 可按名称和时间查到样品 |
| UAT-015 | 查看归档 | 可按样品版本查看需求、实验、测试、寄样、核价文件 |

## 10. 建议开发顺序

推荐顺序：

```text
1. 数据模型
2. 状态机
3. 用户权限
4. 样品需求
5. 任务分发
6. 实验单
7. 内部测试
8. 历史版本和锁定
9. 寄样反馈
10. 核价文件
11. 财务通知
12. 文件归档
13. 搜索筛选
14. 飞书深度联调
15. 验收上线
```

不建议先做漂亮页面再补业务规则。这个系统最核心的是状态、版本、文件和权限，先把骨架立住，页面体验才不会反复返工。
