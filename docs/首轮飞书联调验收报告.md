# 首轮飞书联调验收报告

生成日期：2026-06-21

## 一、验收结论

首轮飞书自建应用研发样品管理系统联调演示能力已具备。

当前系统可以完成从本地环境自检、生成完整演示业务链路、输出人工核对清单、生成机器可读 JSON 报告，到演示前自动校验报告完整性和原型页面入口的闭环。

## 二、已覆盖演示范围

本轮验收覆盖以下研发样品主流程：

1. 研发内勤创建样品需求。
2. 研发总监审核需求。
3. 生成样品项目和 A0 样品版本。
4. 研发总监分发研发任务。
5. 研发人员接受任务。
6. 研发人员填写并保存实验单。
7. 内部测试通过并锁定版本。
8. 生成寄样反馈记录。
9. 生成核价文件记录。
10. 生成财务核价通知记录。
11. 输出演示核对清单。
12. 校验演示报告完整性、页面入口、URL 和清单覆盖性。

## 三、演示前推荐命令

### 1. 本地飞书配置自检

```bash
node scripts/feishu-local-check.mjs
```

通过标准：

- 后端可以访问。
- 飞书 OpenAPI 配置状态明确。
- 输出下一步建议。

### 2. 生成演示链路和人工核对清单

```bash
node scripts/feishu-demo-wizard.mjs
```

通过标准：

- 生成样品编号。
- 生成需求、任务、实验单、测试、寄样、核价和财务通知记录。
- 输出可以逐项打开的演示核对清单。

### 3. 生成 JSON 报告并校验

```bash
node scripts/feishu-demo-wizard.mjs --json > /tmp/feishu-demo-report.json
node scripts/feishu-demo-report.mjs --file /tmp/feishu-demo-report.json --prototype-app prototype-app/app.js
```

通过标准：

- `ready` 为 true。
- `sampleNo` 存在。
- 关键业务 ID 完整。
- 核对清单不少于 6 项。
- 清单覆盖样品编号、任务、实验单、寄样、核价和财务通知。
- `route` 使用 hash 入口。
- URL 格式合法。
- URL hash 与 `route` 一致。
- 原型页面入口真实存在。
- 输出“下一步”建议。

## 六、首轮演示验收标准

达到以下条件，即可安排第一版真实效果演示：

1. 后端服务可启动。
2. PC 原型页面可打开。
3. 飞书应用 App ID 和 App Secret 已配置到本地密钥文件。
4. `node scripts/feishu-local-check.mjs` 给出可继续演示的状态或明确下一步。
5. `node scripts/feishu-demo-wizard.mjs --json` 可以生成完整报告。
6. `node scripts/feishu-demo-report.mjs --file /tmp/feishu-demo-report.json --prototype-app prototype-app/app.js` 校验通过。

1. 确认 `backend/.env.feishu.local` 中 App ID、App Secret、App URL 已填写。
