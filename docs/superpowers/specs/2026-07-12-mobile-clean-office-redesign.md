# 手机端 A「清爽办公」改版设计

## 目标

在不改变研发核价闭环、角色权限和后端接口的前提下，重做手机端视觉层级与操作节奏，使研发内勤、研发总监、研发人员、测试人员和财务能够在小屏设备上快速识别当前任务并完成唯一主动作。

设计关键词：简洁、清晰、轻快、可靠。趣味感来自状态反馈、任务接力和轻量动效，不使用卡通插画、装饰性渐变或复杂动画。

## 设计范围

本轮覆盖：

- 网页账号登录
- 角色工作台与待办列表
- 需求录入、需求审核、任务分配
- 任务详情与实验单
- 内部测试
- 核价生成、核价审核、财务通知、财务接收
- 样品与个人中心的公共视觉
- 局域网访问与登录错误提示

本轮保持兼容：

- 已有需求、打样、测试、寄样和财务接收接口
- 已有角色权限边界；仅增加产品负责人和核价审核权限
- 飞书免登逻辑
- PC 管理端整体布局；只补充核价审核入口

## 视觉系统

### 色彩

- 主色：`#246BFE`，用于主动作、当前状态和关键数字。
- 页面背景：`#F5F7FA`，卡片背景为白色。
- 正文：`#172033`，辅助文字：`#667085`。
- 完成：绿色；待处理：橙色；异常：红色。
- 禁止使用大面积渐变、深色背景和多色装饰块。

### 空间与形状

- 页面左右间距统一为 16px。
- 模块间距 16px，表单字段间距 8px。
- 卡片圆角统一为 8px，按钮圆角 8px，状态标签可使用胶囊形。
- 仅固定操作栏保留轻阴影；普通卡片使用细边框区分层级。
- 标题不随屏幕宽度缩放，避免小屏文字跳动。

### 趣味与反馈

- 工作台使用简短问候和“今天有 N 项任务”建立节奏。
- 任务状态使用单字图标，如“审、样、测、价”，帮助快速扫读。
- 主流程完成后使用短暂勾选反馈和明确下一棒提示。
- 动效仅使用 150-200ms 的淡入、状态切换和按钮反馈。

## 页面结构

### 登录页

- 首屏只展示品牌标识、系统名称、账号、密码和登录按钮。
- 产品介绍压缩为一行，不占用首屏主要空间。
- 快速测试账号放入默认收起的“测试辅助”区域。
- 测试辅助是临时功能，后续删除不影响账号密码表单。
- 登录失败在表单附近显示中文原因，保留重新登录动作。
- 显示当前访问主机；检测到 IP 形式的局域网地址时提示可优先使用 Mac `.local` 固定入口。

固定测试入口：

```text
http://lhrzp-macbook-air-3.local:5174/m/login
```

### 工作台

- 顶部显示用户姓名、角色和问候语。
- 第一层为三个紧凑状态数字，根据角色动态显示，如待审核、打样中、待核价。
- 第二层只展示一个最高优先级任务，包含产品、版本、状态和一个主动作。
- 第三层为紧凑待办列表，每项包含状态图标、产品名、版本、时间和箭头。
- 角色入口不再占用大卡片，改为横向快捷操作或小型工具格。

### 需求、审核与分配

- 需求录入按“产品信息、使用要求、申请信息”分为三个短区块。
- 审核卡直接展示客户、应用场景和风味要求，底部只有“审核通过”主动作。
- 任务分配将人员选择和截止日期放在同一任务卡内，分配成功后从列表移除。

### 实验单

- 顶部固定显示产品、版本、任务状态和完成进度。
- 首次进入仍保留“快速打样 / 编排后打样”两种模式。
- 实验单以生成核价文件所需的数据为主线，不录入包材。
- 配方投入分为一个主料和多个配料。主料记录名称、重量和利用率；配料记录名称和重量；系统自动计算总投入和配方比例。
- 关键工序至少保留一道，每道只记录工序名称、投入重量、余料重量和产出重量，自动计算损耗重量与损耗率。
- 成品产出记录成品总重量、成品数量和数量单位。数量单位默认“袋”，可切换盒、份、个、盘。
- 系统自动计算主料得率、平均每袋重量和参考袋数。
- 保存前展示核价数据预览，包含主料、配料、比例、实际投入、利用率、成品重量、成品袋数和得率。
- 核价必需字段不完整时可以保存草稿，但不能提交内部测试或锁定版本。
- 底部操作栏只显示当前可执行的主动作；保存草稿为次级动作。
- 提交后进入只读状态，并明确显示版本已锁定。

### 测试与核价

- 测试页先显示实验摘要，再显示三个必填测试项和结论。
- “通过并锁版”为唯一主按钮，复打样和停止作为次级动作。
- 测试通过并锁版后才能生成核价文件草稿，初始状态为“待核价审核”。
- 核价详情先显示文件状态和版本，再按权限显示审核、下载、通知财务或确认接收。
- 核价审核人可以是研发总监或任务分配时指定的产品负责人，产品负责人允许审核自己负责的产品。
- 核价审核退回必须填写原因。仅核价文件内容有误时生成同一样品版本下的新核价版本；配方或实验数据有误时生成下一样品版本重新打样。
- 核价审核通过前禁止通知财务。
- 财务页面隐藏研发过程操作，只保留查看、下载和确认接收。

## 业务流程

### 主流程

```text
研发内勤录入需求
-> 研发总监审核
-> 进入任务池
-> 研发总监分配研发人员和产品负责人
-> 研发人员接受任务
-> 创建 A0 样品版本
-> 填写配方投入
-> 记录关键工序损耗
-> 记录成品重量和数量
-> 保存实验单草稿
-> 通知内部测试
-> 测试通过并锁定实验版本
-> 生成核价文件草稿
-> 研发总监或产品负责人审核
-> 审核通过
-> 研发内勤通知财务
-> 财务查看、下载并确认接收
-> 归档
```

### 复打样与停止

- 内部测试不通过时生成 A1、A2、A3 等下一样品版本，重新进入实验单。
- 内部测试建议停止时由研发总监确认，进入停止项目池并归档原因。
- 客户反馈不通过且需要继续打样时，同样生成下一样品版本。

### 核价审核退回

- 配方或实验数据有误：实验单已经锁定，不允许覆盖，生成下一样品版本重新打样。
- 仅核价文件内容有误：样品版本不变，生成新的核价版本，如 `A0-核价V2`。
- 所有被退回和历史核价文件只读保留。

### 可选寄样支线

内部测试通过后可以登记寄样和客户反馈。寄样不阻塞生成核价文件；客户反馈、快递信息和附件独立归档。

## 数据与状态扩展

### 任务与产品负责人

- 任务分配时同时记录研发人员和产品负责人。
- 产品负责人默认可选择被分配的研发人员，也可由研发总监指定其他具有研发审核权限的人员。

### 核价状态

```text
PENDING_PRICING_REVIEW
-> PRICING_APPROVED
-> FINANCE_NOTIFIED
-> FINANCE_RECEIVED
```

退回状态：

```text
PENDING_PRICING_REVIEW
-> PRICING_REJECTED
-> 新核价版本或新样品版本
```

生成核价文件时直接创建 `PENDING_PRICING_REVIEW` 状态。历史 `GENERATED` 记录迁移为待核价审核，不允许绕过审核通知财务。核价记录新增审核人、审核时间、审核意见、退回原因和审核来源角色。通知财务接口只接受 `PRICING_APPROVED` 状态。

## 公共组件调整

- `PageHeader`：支持紧凑标题、角色信息和统计数字。
- `HeroCard`：缩小高度，明确唯一主动作。
- `TaskCard`：增加状态字图标，减少说明文字。
- `RoleEntryGrid`：改为紧凑快捷操作。
- `FixedActionBar`：统一按钮层级和安全区间距。
- `InfoCard`：减少卡片嵌套，详情字段保持两列对齐。
- `StatusBadge`：统一状态色和标签尺寸。
- 颜色、圆角、阴影、间距全部收敛到 design tokens。

## 登录稳定性

局域网登录链路为：

```text
手机浏览器 -> Vite 5174 -> /api 代理 -> Spring Boot 8080
```

已确认账号和登录接口正常。此前失败由局域网 IP 从 `192.168.134.56` 变化为 `192.168.133.125` 引起。改版需：

- 登录失败时区分“账号密码错误”和“服务无法连接”。
- 网络异常显示当前页面主机和建议入口。
- 文档与启动脚本优先输出 `.local` 地址，同时输出当前 IP 作为备用。
- 不在手机前端写死局域网 IP，API 始终使用同源 `/api/v1`。

## 错误与空状态

- 所有列表加载失败显示错误摘要和“重新加载”。
- 表单提交失败保留用户输入。
- 空状态说明下一步可做什么，不展示无意义的大图。
- 下载失败、会话过期和无权限使用不同中文提示。

## 验收标准

- 375px 宽度下无横向滚动、遮挡或文字溢出。
- 登录首屏无需滚动即可看到账号、密码和登录按钮。
- 每个业务页面在固定操作栏中最多显示一个主按钮。
- 五个角色登录后看到不同且正确的入口和待办。
- 产品负责人能够看到自己负责产品的待核价审核任务并完成自审。
- 核价审核通过前，研发内勤和财务均不能执行财务移交。
- 核价审核退回后，旧核价版本保持只读并可查询。
- 局域网固定主机名可打开登录页并完成登录。
- 原有五角色闭环自动化测试继续通过。
- PC/手机构建、类型检查、接口契约和路由检查全部通过。

## 后续移除测试账号

快速测试账号区域必须与登录主表单解耦。正式上线时只删除测试账号配置及折叠区组件，不修改认证接口、登录表单、路由守卫或权限逻辑。
