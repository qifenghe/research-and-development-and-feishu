# 研发小步骤参数与配方入口设计

状态：待用户审阅。第一步拖拽修复独立交付；本文的参数结构及后续页面尚未实施。

## 目的与边界

研发人员先编排大工序，再记录可复现的小步骤。大工序承载主料投入、产出及得率；小步骤承载操作参数、投料时机、过程说明、产出与关键控制点。界面默认简洁，展开才出现详细录入项。

保持现有主料得率计算和版本权限，不修改食品工艺标准，不自动填写未经确认的温度、时长或尺寸。新增参数不参与重量计算。真实产品对账需要用户提供记录，软件测试不能替代工艺验证。

## 阶段安排

1. 修复空白工序拖入、重复拖入、新步骤选中和点击添加（当前独立修复）。
2. 实施可扩展小步骤参数及投料时机，贯通保存、复制、比较、正式快照和 SOP。
3. 增加直接可见的配方汇总入口，明确试验与正式版本的区别。
4. 用真实产品核对配方与得率；记录差异，不为得到预期结果而修改计算口径。

## 小步骤参数

每个参数有稳定键、名称、类型（数值/文字）、单位、实际记录值以及可选下限/上限。允许增加、删除和排序；缺失值不是零。数值字段拒绝非有限数值，比较只在同名同单位且数值完整时计算偏差；单位不同提示不可直接比较。

操作模板仅提供字段，不提供生产标准值：

| 操作 | 默认展开的录入项 |
| --- | --- |
| 分切/切块 | 长、宽、高（mm），尺寸允许偏差，切割方式 |
| 煮制/焯水 | 温度（℃）、时长（min）、计时起点、加热方式、结束判断 |
| 煎炒/油炸 | 温度、时长、翻动/搅拌要求、结束判断 |
| 腌制/滚揉 | 时长、温度、设备操作说明 |
| 冷却/冻结 | 时长、目标温度、结束判断 |
| 其他 | 可自行添加参数及操作说明 |

切换模板不能默默删除已有参数或实测。已有两个通用参数在新界面无损映射为列表，旧正式快照及已归档文件不改写。新旧参数兼容读取，写入采用明确的新结构，避免同一参数两份值互相覆盖。

计划值和实际值分开：新增参数以稳定键关联计划值，复制方案时同步重映射；结构复制清除实际值，继承实测复制明确标记来源。删除参数清理其计划关联，不能留下悬空键。参数定义变化使旧偏差不再可直接比较。

## 投料时机

每条投料在物料、主辅角色、重量、来源之外增加“加入时机”和“加入方式”文字字段。例如“水沸后加入”“分三次加入”。重量为空时仍为待补充，不从文字描述推算重量。

同一种料分次添加保留多条投料记录；配方汇总合计外部投入，展开显示所在工序、步骤、各次重量与时机。中间产物仍为当前版本内部引用，不加入物料库，也不重复算入外部配方。不同物料身份不能仅因同名而合并。

## 页面与版本

顶部明确区分“试验方案（打样修改）”和“正式版本（确认留档）”。研发进入时优先展示已有试验方案；没有方案时提示新建，不在访问页面时自动创建或提交。既有正式草稿保留并提供清晰说明，不静默迁移或覆盖。

小步骤折叠时展示名称、关键参数摘要与投料项数。展开包含：操作参数、投料与加入时机、产出、中间状态、关键控制点。重要控制点继续沿用确认与偏差闭环，不用一般参数替代。

顶部增加“配方汇总”入口：当前页面的未保存数据可查看并标记“未保存”；文件预览/下载必须绑定已保存方案或明确正式版本，不能混用两份数据。汇总展示主辅料、用量、单位、比例及来源步骤；实际投料与每100kg折算分开。缺失重量时不展示假完整总量或比例。

## 导出与完整性

新增参数和投料时机必须进入对应版本 SOP，配方明细能追溯投料步骤。核价仍只列基础数据，无金额和最终成本计算。

一并补齐现有 SOP 预览问题：正式生成、检查弹窗和预览文件使用同一份检查结果。无名称但有值、数值缺单位等情况在预览中显示明确待补充项，不隐藏已录值；不完整预览仍允许下载，正式生成保持拦截。旧归档下载不受新增门槛影响。

## 验收

- 空白区及已有步骤可重复拖入，新增项独立并自动选中；只读不能修改。
- 多于两个参数保存刷新不丢失；切块长宽高、煮制温度时长与计时起点均可记录。
- 结构复制、继承复制、计划偏差、删除关联、正式提交与历史版本分别验证。
- 分次投料合计正确，中间产物不重复计料；缺失、零和小数重量分别验证。
- 页面、保存结果、SOP 和配方同源；检查预览缺名/缺单位的文档内容与实际排版。
- 新增参数不改变既有主料得率；连续流测试90%×80%=72%，加汤后的包装重量保持独立。
