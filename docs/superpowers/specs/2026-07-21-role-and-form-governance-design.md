# 角色、权限与表单配置设计

## 目标

让超级管理员能够在网页端建立角色、给角色分配菜单和增删改查审核导出权限，并把角色分配给账号；同时让需求单、实验单、测试单、寄样反馈、核价文件五类表单字段可视化配置。关键业务规则由后端强制执行：研发总监能查看测试，产品负责人或研发总监审核核价，财务只在核价审核通过并移交后可见。

## 角色模型

- 一个账号只分配一个启用角色。
- 角色是可维护的主数据：编码、名称、描述、启用状态、系统内置标记。
- 系统内置角色包括研发内勤、研发总监、研发人员、测试人员、财务、超级管理员；可建立自定义角色。
- 系统内置超级管理员不可删除或停用为无可用超级管理员状态。
- 账号引用角色编码；禁用角色前必须确保没有启用账号使用该角色。

## 权限模型

每个角色可按功能模块勾选操作：查看、新增、编辑、删除、提交、审核、导出、下载、通知财务。权限配置同时生成 API 访问规则，后端以规则为准，前端仅用于隐藏无权入口。

数据范围为：本人、本人负责产品、全部。产品负责人资格由研发任务的 `productOwnerName` 确定，不是额外角色。

模块范围：样品需求、研发任务与实验单、内部测试、寄样反馈、核价文件、报表归档、系统设置。

## 表单配置

配置中心固定展示五种表单：`SAMPLE_REQUEST`、`EXPERIMENT_FORM`、`TEST_RECORD`、`SHIPMENT_FEEDBACK`、`PRICING_FILE`。

每种表单支持新增、编辑、停用、删除字段；字段可配置编码、名称、控件类型、必填、启用、顺序、默认值、提示、字典来源和说明。系统关键字段不允许删除，只允许改显示名称、提示和排序，避免破坏已实现业务接口。

## 关键业务规则

1. 研发总监可查看所有待测试/已测试任务、测试结论和测试单导出。
2. 测试人员仅可填写被分配的测试任务。
3. 核价文件生成后为待审核状态；研发总监可审核所有核价文件，产品负责人仅能审核本人负责产品的核价文件。
4. 财务只能查询、下载和确认“已审核且已通知财务”的核价文件；前端和后端都必须拦截其他文件。
5. 核价审核退回后保留原版本，重新生成下一核价版本。

## 审计与验收

角色、权限、表单字段、账号角色变更均写入审计日志。验收包括：超级管理员建立角色、分配权限、账号引用角色；权限变更即时影响接口；五类表单显示默认字段并可维护；总监可查测试；产品负责人审核后财务才可见核价文件。
