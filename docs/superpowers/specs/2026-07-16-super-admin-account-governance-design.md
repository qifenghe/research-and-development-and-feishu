# 超级管理员与账号治理设计

## 目标

系统现阶段独立以网页端运行，不依赖飞书身份。新增独立的超级管理员治理能力，使账号创建、角色分配和账号状态维护有明确的责任边界，同时保留现有研发、测试、财务业务流转权限。

## 角色模型

每个账号只分配一个主角色。权限由主角色决定，不支持普通业务账号叠加多个角色。

| 主角色 | 业务权限 |
| --- | --- |
| 研发内勤 | 创建、保存、修改、提交样品需求；登记寄样和客户反馈 |
| 研发人员 | 接受研发任务；填写、保存、提交实验单；查看本人任务与历史版本 |
| 研发总监 | 继承研发人员权限；审核需求；分配、转派研发任务；审核核价文件；可作为产品负责人参与研发 |
| 测试人员 | 接收内部测试任务；提交测试记录和测试结论 |
| 财务 | 查看、下载已审核并移交的核价文件；登记已接收状态 |
| 超级管理员 | 拥有全系统配置与账号治理权限，不以业务办理为主要职责 |

研发总监的权限采用“包含研发人员权限，再增加管理权限”的继承方式，不需要为同一人增加第二个角色。

## 超级管理员边界

仅超级管理员可以访问“系统设置 / 人员与权限”。该模块包含：

- 新建网页端账号，设置初始密码、姓名、部门和主角色。
- 编辑账号基础信息与主角色。
- 重置密码、启用和停用账号。
- 查看最近登录时间和账号状态。
- 配置业务角色的菜单和操作权限。

普通业务角色不能进入人员配置接口或页面。系统管理员也不得通过页面或接口将自己提升为超级管理员，不能停用或删除最后一个启用中的超级管理员。首版不做账号删除，避免审计记录断裂。

## 数据与接口

沿用 `user_account` 的 `username`、`password_hash`、`role`、`status`、`last_login_at` 字段。飞书用户 ID 保持可空，仅作为未来绑定字段，不参与当前网页登录。

新增或调整的接口行为：

- 登录接口仅接受启用状态的网页端账号和密码。
- 用户列表、新建、编辑、重置密码、启停接口都要求超级管理员权限。
- 新建账号默认启用，初始密码由超级管理员填写；若不填写，系统明确显示并使用 `123456`。
- 角色权限配置接口仅允许超级管理员访问。
- 所有账号治理操作写入审计日志，包含操作者、目标账号、操作类型、时间和变更摘要。

## 前端

PC 管理端保留“人员配置与权限”入口，但仅在超级管理员登录时展示。页面标题调整为“账号与权限”，突出网页账号而非飞书账号。列表展示账号、姓名、主角色、部门、状态、最近登录和操作；飞书 ID 隐藏到“后期身份绑定”折叠项。

手机端不提供人员配置，避免移动端误操作。手机端根据当前角色展示业务入口。

## 安全与约束

- 密码只保存哈希，前端和用户列表不返回密码哈希。
- 停用账号后立即禁止新登录；已签发令牌在首版可自然过期，后续可补令牌撤销。
- 账号名全局唯一。
- 系统初始化至少创建一个 `SUPER_ADMIN` 账号，启动日志不打印密码。
- 用户创建、角色变更、密码重置、启停都记录审计日志。

## 验收

1. 超级管理员可登录并创建研发内勤、研发总监、研发人员、测试、财务账号。
2. 超级管理员可以为每个账号分配唯一主角色，并可修改角色。
3. 研发总监可同时执行研发和审核/分配/核价审核操作。
4. 普通业务账号无法访问人员配置和角色权限接口，即使手工输入 URL。
5. 停用账号不能登录；重置密码后只能用新密码登录。
6. 保留至少一个启用中的超级管理员。
