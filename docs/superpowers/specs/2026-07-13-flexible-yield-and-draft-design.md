# 灵活得率与可靠打样草稿设计

## 目标

将打样实验单调整为面向核价文件的统一录入模型，同时解决页面切换导致未保存数据丢失的问题。系统必须同时支持无主料酱汁、多主料肉制品和普通单主料产品。

## 统一业务模型

实验单增加 `yieldCalculationMode`：

- `SELECTED_PRIMARY_MATERIALS`：按研发勾选的一项或多项主料计算得率。
- `TOTAL_PICKING_WEIGHT`：不要求主料，按全部非包材物料的领料重量计算得率，适用于酱汁、复合调味料等产品。

每一行配方保留 `materialCategory`（原料、辅料、包材）与 `primaryMaterial`（是否计入主料基准）两个独立字段。主料可以为 0、1 或多项；包材永不进入得率基准。

统一计算公式：

```text
领料重量 = 配方重量 / 利用率
主料模式得率基准 = 所有已勾选主料的领料重量之和
总领料模式得率基准 = 所有非包材物料的领料重量之和
研发参考得率 = 成品产出重量 / 得率基准重量 * 100%
参考数量 = 成品产出重量 / 单份规格重量
```

利用率默认 100%。旧实验单没有该字段时默认使用主料模式，确保历史数据兼容。

## 页面流程

删除 PC 和手机端的“快速打样/编排后打样”选择页。进入实验单后直接显示工序编排；研发确认工序后开始逐步打样，仍可返回调整工序。

配方区增加得率基准选择：

- 选择“按主料计算”时，每行可独立勾选“计入主料”，允许多选。
- 选择“按全部物料计算”时，不要求选择主料，并提示包材不参与计算。

核价预览统一显示“得率基准重量”和“研发参考得率”，不再使用“主料得率”这一只适用于单主料产品的名称。

## 草稿保护

PC 和手机端采用两层保存：

1. 用户每次修改后立即写入浏览器本地草稿，切换页面、刷新或关闭标签后仍可恢复。
2. 停止输入约 1.5 秒后自动调用后台保存草稿接口，保存成功后显示“已自动保存”。

本地草稿按用户和任务隔离。重新进入页面时，比较本地与服务端保存时间，恢复较新的版本；实验单提交锁定后清除本地草稿，禁止旧草稿覆盖锁定版本。自动保存失败时保留本地数据并明确提示，不阻塞继续录入。

## 后端校验

- 草稿允许不完整，不因尚未选择主料而拒绝保存。
- 提交测试前，主料模式至少选择一项有效主料；总领料模式至少有一项有效非包材物料。
- 允许多个主料；主料必须属于原料类别。
- 非主料可以是原料或辅料，不再强制全部变成辅料。
- 得率由后端按统一公式重算，不信任前端传入的百分比。

## 核价 Excel

核价文件沿用现有正式模板格式：

- 主料模式：得率公式分母为所有已勾选主料的领料重量合计。
- 总领料模式：得率公式分母为全部非包材物料的领料重量合计。
- 表头使用“研发部参考得率(%)”，避免将酱汁误标为主料得率。
- 同一配方中的多项主料在原料清单中正常逐行展示，不合并、不丢失。

## 验收标准

1. 酱汁实验单可在没有主料的情况下保存、提交并生成正确得率的核价文件。
2. 两项及以上主料可同时勾选，得率分母是这些主料领料重量之和。
3. 手机或 PC 切换页面后返回，刚刚填写的数据仍存在。
4. 后台自动保存失败时，本地草稿仍可恢复。
5. 提交锁定后不能被本地旧草稿覆盖。
6. PC、手机、后端和 Excel 对得率的计算结果一致。
